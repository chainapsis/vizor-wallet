# 모바일 Ledger 흐름 검증

연결 준비, 기기 승인, Vizor의 마무리 처리를 구분합니다. 화면 캡처는
[PR #998](https://github.com/chainapsis/vizor-wallet/pull/998)의 본문 첨부로 관리합니다.
Flutter 위젯을 테스트 fixture로 렌더하며 Ledger·Bluetooth·저장소 응답은
제어된 테스트 응답입니다. 실물 기기 촬영이나 성능 측정은 아닙니다.

연결 화면의 Advanced options는 잔액·활동 안내 위에 배치합니다. 연결을 시작하면
자동으로 기기를 검색하고, 기기를 고르면 Zcash 앱 확인과 viewing key 승인으로
이어집니다. 승인 시트 위의 뒤로가기는 진행 중 요청을 취소한 뒤 기기 선택으로
돌아갑니다.

Send는 고정된 PCZT에서 proof 생성과 Ledger 서명을 병렬로 시작합니다.
Reject 이후 재시도는 준비 완료 표시를 유지하고 승인 단계에서 이어집니다.
TEX는 기기 승인을 순차적으로 요청하며, 이미 받은 서명은 재사용합니다.
Proof가 실패했고 승인이 남아 있으면 진행 중 기기 요청의 종료를 기다리고 연결을
다시 선택한 뒤 아직 서명하지 않은 트랜잭션부터 재시도합니다. 승인이 모두 끝났다면
추가 승인 없이 proof만 다시 시도합니다. 두 작업이 모두 완료된 뒤에만 서명된
트랜잭션을 저장합니다.

## 자동 검증

- 공용 UI: 단계 번호·제목 정렬, 안내 펼침·접힘, 동작 줄이기, 큰 글자와 좁은 화면,
  Bluetooth 복구, 작업별 승인·취소 안내를 검증합니다.
- 연결: 기기 재선택, 늦게 도착한 응답 무시, 취소 완료 전 화면 이탈 방지,
  Advanced options 입력 검증, 생일·첫 계정 생성으로의 이동을 검증합니다.
- Send: proof·서명의 두 완료 순서, 실패 후 종료 대기, 진행 중 proof 재사용,
  Reject 후 준비 상태 유지, TEX 부분 서명 보존, 저장 재시도를 검증합니다.
- Speculos: iOS 26.3.1 시뮬레이터와 Zcash 앱 3.9.4에서 9개 시나리오가
  최종 통과했습니다. 가져오기, Send의 Reject 재시도, Orchard 호환성 차단,
  TEX 연속 승인, TEX proof 실패 복구, Shield, Pay, Swap, Voting을 포함합니다.

Speculos는 실제 펌웨어/APDU 서명과 Rust 저장·전송 경로를 실행합니다.
물리 Bluetooth 대신 HTTP 전송을 사용하며, 로컬 lightwalletd stub이 트랜잭션을
수신합니다. 실기기 페어링·OS 권한, 실제 체인 전송·확정·잔액 동기화는 이 검증에
포함되지 않습니다. 온보딩은 입력한 생일 높이와 mainnet 프라이버시 규칙에 따라
저장되는 스캔 시작 높이를 각각 검증합니다.

실행 방법과 펌웨어 버전은 [Speculos E2E 문서](../speculos.md)를 참고하세요.
