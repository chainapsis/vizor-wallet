# Vizor 계약 참고 규칙과 직접 라우팅

2026-09-13 · `rowan/agent-contract-docs` · 시작 HEAD `efbc2f3dea804a0a6b94a3a7f42af3feffc9f41b`

## 목표와 범위

작업 전에 관련 계약만 읽고 현재 코드에서 적용 지점을 확인할 수 있게 한다.
AGENTS는 공통 실행 규칙과 작업별 진입점을 맡고, 행동 계약은 기존 문서를 정본으로
유지한다. 문서 크기나 파일 수 자체를 줄이는 작업은 아니다.

현재 계약 98개 중 22개가 색인이다. 루트는 4,881 bytes / 96줄이며 제품·공통·OS
색인을 먼저 안내한다. Keplr의 관련 규칙 선택 방식을 참고해 명확한 작업은 영역
색인이나 세부 계약으로 직접 연결한다. 이 크기는 토큰이나 실행비용 측정값이 아니다.

기존 계약·색인·그래프 도구와 과거 실험 기록은 보존한다. 그래프는 기본 읽기 경로에서
제외한다. 코드·주석 일괄 수정, 새 벤치마크, 영구 메모리 저장, 커밋·푸시는 포함하지 않는다.
Vizor 로컬·원격 main과 다른 워크트리를 변경하지 않는다.

## 실행 순서와 담당

1. **직접 라우팅 검토:** Sol / Medium 서브에이전트가 기존 진입점과 공백을 확인한다.
   루트 담당자는 AGENTS의 기본 읽기 순서를 갱신한다.
2. **유지 규칙 작성:** 루트 담당자가 짧은 계약 작성·갱신 규칙을 CONTRIBUTING에 둔다.
   작업 범위, 반드시 지킬 동작·예외, 근거 코드·기존 테스트를 보존하고 구현 서술은
   필요한 만큼만 둔다. 루트에 불필요한 환경 상세는 해당 가이드로 옮긴다.
3. **대표 계약 검토:** 같은 서브에이전트가 Send navigation/broadcast, lock/unlock,
   account balances 네 문서를 검토한다. 의미를 바꾸는 압축은 하지 않는다. 기존
   검증 진입점이 빠진 경우에만 실제 테스트를 확인해 링크를 보강한다.
4. **독립 확인과 마감:** 루트 담당자가 로컬 링크·앵커·대표 탐색 경로·diff를 검사한다.
   서브에이전트는 최종 루트를 읽고 누락·불필요한 필수 읽기를 확인한다.

추가 검토자 생성은 런타임 thread limit에 걸려, 기존 Sol 에이전트 한 명을 검토별로
재사용한다. 구현과 최종 검증은 루트 담당자가 맡는다.

## 수용 기준

- 작업을 알면 루트에서 해당 영역 색인 또는 세부 계약으로 바로 간다. 상위 전체
  색인·다른 영역·링크된 문서 전체를 먼저 읽도록 요구하지 않는다.
- 계약이 없는 작업은 관련 코드·호출처·테스트에서 시작하며, 규칙이 없다는 이유로 멈추지 않는다.
- FVM·mobile lane·FRB codegen·Figma 변경 권한·regtest 실행 조건을 보존한다.
- 계약 변경 조건과 검증 포인터는 명확히 하고, 중요한 순서·예외·로컬 주석은 유지한다.
- 기존 문서 검사기를 재사용해 Markdown 대상·앵커를 확인하고 소스·테스트 링크도 확인한다.
- Send 취소, Receive, 잠금, Swap/Pay, Voting, Linux keyring, copy, Figma의 대표 경로를
  정적으로 확인한다. 이를 모델 실행 성공이나 토큰 절감으로 해석하지 않는다.
- 이번 허용 문서 외 기존 변경과 main ref가 작업 시작 상태와 같은지 해시로 확인한다.
  문서 변경이므로 Flutter/Rust 런타임 테스트는 실행하지 않는다.

## 완료 기록

완료. AGENTS에서 16개 작업 영역을 기존 영역 색인 또는 세부 계약으로 직접
연결했다. 상위 domain/shared 색인은 소유자가 불명확할 때만 사용하고, 그래프
안내는 루트에서 제거했다. 기존 그래프 도구·문서와 98개 계약/색인은 보존했다.

CONTRIBUTING에 계약 유지 규칙을 추가하고, 루트의 로그·의존성 상세를 setup으로
옮겼다. Send broadcast에는 기존 Dart/fake-Rust·secret-session 테스트를 연결했다.
Unlock에는 parked-request 화면 테스트와 provider recovery를 stub한다는 한계를
명시했다. 네 대표 계약의 행동 본문은 재작성하지 않았다.

Sol / Medium 에이전트가 라우팅, 네 계약, 최종 diff를 순차 검토했다. 최종 검토에서
빠진 simulator reset 진입점을 발견해 AGENTS에 `clear-app.sh`/Keychain reset
라우팅을 보완했다.

- 루트: **96 → 73줄, 4,881 → 4,970 UTF-8 bytes**. 직접 링크로 89 bytes 늘었다.
  바이트·토큰 절감을 달성한 변경으로 표현하지 않는다.
- 대표 경로 10개를 정적으로 확인했다. 제품/shared 작업은 상위 전체 색인을
  건너뛰며, Receive와 Figma처럼 이미 직접 연결됐던 작업은 추가 단계를 만들지 않는다.
- 101개 문서의 로컬 링크·Markdown 앵커 **619개**를 확인했다.
- 기존 문서 그래프 도구 테스트 **12개 통과**, `git diff --check` 통과.
- 이번 허용 문서 외 기준본 **115개 경로**의 내용/존재 상태와 main ref를 대조해
  동일함을 확인했다. 기존 코드 수정과 다른 워크트리는 보존했다.

앱 테스트·빌드·모델 벤치마크·전체 계약의 현재성 재감사는 실행하지 않았다.
커밋·푸시·설치·영구 메모리 기록 없이 이 워크트리의 문서 변경으로 완료했다.
