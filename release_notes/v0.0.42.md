# Vizor Wallet v0.0.42

This release gives you more control over active Ironwood migrations and
improves migration, synchronization, and Pay reliability.

## If a Migration Is Already in Progress

- Updating does not interrupt an existing migration. After updating, unlock
  Vizor and your migration will resume from its saved progress and schedule.
- Existing migration schedules and saved timing policies remain unchanged.
  The updated proof timing applies only to newly started migrations.
- You can update now or let your current migration finish first. No action is
  required if the migration is progressing as expected.
- If you want to change course, you can now stop the remaining scheduled
  transfers and restart the migration from the home page. Transfers already
  submitted to the network cannot be reverted.

## What's New

- Active private migrations can now be managed from the migration schedule.
  You can switch the remaining balance to an immediate migration or stop the
  remaining scheduled transfers and restart later.

## Improvements

- New Ironwood migrations now wait for a more established chain anchor before
  proofs begin. This may add preparation time.
- Synchronization progress now remains informative while Vizor repairs wallet
  scan data.
- Pay now shows complete, payment-specific error messages and clearer asset
  network details.

## Fixes

- Fixed confirmed migration transfers sometimes remaining stuck as **Due now**
  or **Sending now**, preventing later transfers from proceeding.
- Improved recovery when a migration transfer reaches the network but cannot
  immediately be saved to the local wallet.
- Fixed startup synchronization potentially hanging while refreshing
  transparent funds from an unresponsive server.
