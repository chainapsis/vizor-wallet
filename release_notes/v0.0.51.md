# Vizor Wallet v0.0.51

This release improves voting reliability and privacy, makes voting submissions
more resilient to interruptions and slow servers, and helps reduce wallet
fragmentation during regular sends.

## If a Migration Is Already in Progress

- Updating does not interrupt an existing migration. After updating, unlock
  Vizor and your migration will resume from its saved progress and schedule.
- Existing migration schedules and saved timing policies remain unchanged.
  The updated proof timing applies only to newly started migrations.
- You can update now or let your current migration finish first. No action is
  required if the migration is progressing as expected.
- If you want to change course, you can now stop the remaining scheduled
  transfers and restart the migration from the home page. Transfers already
  submitted to the network cannot be reverted.

## Improvements

- Pending voting submissions are now recovered after restarting or unlocking
  Vizor, so accepted voting work can continue without keeping the voting screen
  open.
- Voting configuration now uses authenticated fallback sources when a built-in
  source is unavailable, improving voting availability without weakening
  configuration verification.
- Test voting rounds are now hidden by default. They can be shown from Voting
  config when needed.
- When a small amount of voting power is excluded to make a submission less
  identifiable, the proposal screen now shows the excluded amount before you
  vote.
- Regular sends can now consolidate additional shielded notes when possible
  without changing the transaction shape, helping reduce wallet fragmentation
  over time.

## Fixes

- Reduced long voting submission delays when one or more voting servers are
  slow or unavailable.
- Improved voting submission persistence so completed shares are saved more
  reliably during temporary local database contention or partial failures.
