# Vizor Wallet v0.0.50

This release makes externally received funds available sooner, reduces sync
waiting, and improves wallet responsiveness, voting availability, and network
reliability.

## If a Migration Is Already in Progress

- Updating does not interrupt an existing migration. After updating, unlock
  Vizor and your migration will resume from its saved progress and schedule.
- Existing migration schedules and saved timing policies remain unchanged.
  The updated proof timing applies only to newly started migrations.
- You can update now or let your current migration finish first. No action is
  required if the migration is progressing as expected.
- If you want to change course, you can now stop the remaining scheduled
  transfers and restart the migration from the home page. Transfers already
  submitted to the network cannot be reverted.

## Improvements

- Externally received shielded funds now become spendable after six
  confirmations instead of ten. Wallet-created change remains available after
  three confirmations.
- Reduced avoidable network waiting during wallet catch-up by downloading
  independent sync data in parallel and preparing upcoming scan data earlier.
  This is most helpful during long recoveries and on slower or Tor connections.
- Multi-account wallets now prioritize the selected account during sync, so
  its balance and activity become current sooner. Other accounts continue
  refreshing shortly afterward.
- Sync progress now advances during preparation instead of remaining at 0%,
  while Home and wallet content avoid unnecessary refreshes.
- Improved voting reliability with a fallback configuration service and
  updated compatibility with current voting services.

## Fixes

- Sync now detects incomplete, duplicated, or out-of-order block data earlier
  and retries through normal network recovery.
